# 发布前还缺什么：iOS 与 Web 的收口计划

## 现状核对（已读代码确认）

- 依赖里没有任何 Supabase / 后端客户端，`src/routes/` 下也没有 API 路由：账号、邀请码、资料、匹配、对话全部存在浏览器 `localStorage`（`src/lib/auth.ts`、`invites.ts`、`profile.ts`、`connections.ts` 等）。
- 邀请码是前端写死的种子白名单（`KINDRED2026` / `WELCOME` / `FRIENDS`），任何人查看源码即可绕过。
- `public/` 只有 `favicon.png`；没有隐私政策、服务条款、账号删除入口，没有社交分享图。
- iOS 侧结构已完备（`native/`、版本号同源、CI 隔离校验），缺的是**上架必需的合规与内容项**，不是工程结构。

结论：工程与结构已经可发布；真正阻塞发布的是**数据只存在单台设备**和**Apple 审核合规缺项**这两件事。

## 阶段一：真实后端（发布的硬前提）

没有这一步，用户换设备就丢全部数据，双向匹配也不可能真实成立（现在“对方”是本地种子数据）。

1. 启用 Lovable Cloud，建表：`profiles`、`invite_codes`、`intents`（心愿/含城市与时间）、`matches`、`messages`、`saved_people`、`saved_intents`、`sessions`。全部按 RLS + GRANT 规范收口，本人只能读写自己的行；匹配对象只暴露资料里标记为可见的字段。
2. 真实登录：Google / Apple 托管登录（微信留待后续），注册时在服务端校验并消费邀请码（放进 server function，前端不再持有码表）。
3. 匹配从前端算法搬到服务端：同城 + 同项目 + 时间重叠为硬过滤，双方均已发布即成立匹配并自动开聊。
4. 迁移策略：首次登录时把本地 `localStorage` 数据一次性上传到账号，之后本地只做缓存。

## 阶段二：Apple 审核必备项

1. **隐私政策 / 服务条款页面**：新增 `/privacy`、`/terms` 两个路由（应用所有者口径的自述内容，具体条款文案由你确认后填入），并在登录页、Me 页加链接。App Store Connect 必填隐私政策 URL。
2. **账号删除**（Apple 5.1.1(v) 强制）：Me 页提供“删除账号”，服务端级联删除全部个人数据。
3. **App Privacy 数据声明**：按实际采集项（姓名、邮箱、头像、城市、用户内容）列表化，写进 `native/docs/ios-build.md` 供你照填。
4. **审核账号 + 可用邀请码**：准备一个永久有效的审核专用邀请码与演示账号，写进提审备注。
5. **举报与屏蔽**（社交类 App 的 1.2 条款）：对话与资料页加“举报 / 屏蔽”，屏蔽后互不出现在匹配池。缺这一项社交产品被拒概率很高。
6. 资产核对：1024 App 图标无透明通道、6.7"/6.5" 截图、启动屏在刘海机型与 iPad 上无拉伸。

## 阶段三：Web 发布质量

1. 每个内容路由补齐独立 `head()`：标题 / 描述 / og:title / og:description / og:type / twitter:card（当前路由基本缺失），并生成一张品牌社交分享图。
2. 错误与离线兜底：全局错误页与 404 页面走品牌样式；断网时给出明确提示（iOS 内嵌产物也共用）。
3. 基础可观测性：接入现有 `error-capture` 上报链路，确认线上报错能看到；发布后跑一次安全扫描。
4. 首屏体验：字体与首屏包体检查，移动网页首次进入不出现闪白。

## 阶段四：发布流程本身

1. Web 先发布到 Lovable 域名，再按需接自有域名（隐私政策 URL 需要稳定域名，最好先定下来）。
2. iOS 走 TestFlight 内测一轮：离线启动、启动屏、安全区、键盘、返回手势、头像上传、登录回跳七项真机验收。
3. 发版清单固化进 `native/docs/ios-build.md`：`version:sync` → `native:build` → `ios:sync` → Archive → 上传。

## 建议的执行顺序

阶段一 → 阶段二 → 阶段三 → 阶段四。阶段一不做完，阶段二里的“删除账号”“举报屏蔽”都没有真实数据可操作，等于白做。

## 技术说明

- 后端统一用 Lovable Cloud + `createServerFn`（不引入 Edge Function）；敏感逻辑（邀请码校验、匹配计算、删除账号）全部只在服务端执行。
- 前端各 `src/lib/*.ts` 保持现有函数签名，内部实现从 `localStorage` 换成 server function 调用，UI 层尽量零改动。
- `native/` 结构与 CI 隔离校验不动；后端接入后 `native:build` 产物仍是纯静态，离线仅展示缓存内容。
