# 分层校验结论与补齐方案（零产品改动）

## 校验结果：主干已分层，但有 4 处会在接后端时被迫改页面

已做到的部分（核查通过）：

- `src/data/ports` 定义 8 个全异步 Repos 接口，`src/data/index.ts` 是唯一装配点，`adapters/remote` 骨架已按端口对齐。
- UI 层没有任何 `data/adapters/*` 的直接 import。
- 组件已改为消费 `@/data/hooks`（例如 `profile-form.tsx` 用 `useProfile` / `useSaveProfile`，不再自己读写存储）。
- `src/routes/*`、`src/components/*` 里剩下的 `sessionStorage` 全是 UI 态（返回地址、滚动位置、草稿、聚焦输入框），与后端无关，属于允许项。

仍未分层的 4 处（接入真实后端时必须改页面代码，正是要避免的）：

1. **人物目录是同步的种子数组。** 8 个 UI 文件直接 `import { getPersonById, avatarUrl, localized } from "@/lib/people"`（`workspace-header`、`saved-trigger`、`connections`、`side-by-side`、`matchmaker`、`meet-canvas`、`intro-canvas`、`connection-thread`、`public-profile-sheet`）。真实后端里“人”来自接口、是异步且分页的，届时这些同步调用点全部要改。端口层目前**没有** people 相关 repo。
2. **Agent 侧的持久状态没有端口。** `src/lib/agent.ts`（会话状态）、`agent-memory.ts`（跨心愿特质）、`understanding.ts`（想要/回避画像）各自直接读写 `localStorage`，且 `side-by-side.tsx` 直接 `import { lastTrait, rememberTrait }`。这些数据接后端后必须落库，现在没有可替换的接缝。
3. **假数据与真实现混在一起。** `adapters/local/index.ts` 单文件 226+ 行 + `lib/people.ts` / `people-extras.ts` / `agents/*` 里的随机回复与模拟延时散落各处，没有可整目录删除的 `fake/seed` 边界。
4. **没有回归护栏。** 目前只靠约定；下一次 UI 迭代很容易再写一行 `import { loadProfile } from "@/lib/profile"` 而 CI 不报错。

## 补齐方案（4 步，全部为结构改动，页面渲染结果与交互逐像素不变）

### 第 1 步：新增 `PeopleRepo`，把人物目录变成可替换数据源

- `ports/index.ts` 增加：
  `get(id): Promise<Person | null>` / `getMany(ids): Promise<Person[]>` / `pool(query?: PageQuery): Promise<Page<Person>>`。
- `adapters/local` 用现有 `PEOPLE` 实现（立即 resolve），行为与今天一致。
- 新增 `hooks/use-people.ts`：`usePerson(id)`、`usePeopleLookup(ids)`，沿用已有 `useIntentLookup` 的“先给同步 map、后台补数据”写法，避免页面出现新的 loading 分支。
- UI 改为 `usePerson(id)` 取代 `getPersonById(id)`。`avatarUrl` / `localized` 是纯函数（不碰存储），保留在 `lib/people`，UI 可继续直接用。

### 第 2 步：为 Agent 状态补 3 个端口

- `AgentStateRepo`（会话内状态，对应 `lib/agent.ts` 的 load/save/clear）
- `AgentMemoryRepo`（`rememberTrait` / `lastTrait`）
- `UnderstandingRepo`（`load` / `save` / `reset`）

纯函数部分（`digest`、`removePositive/Negative`、算分与文案生成）留在 `lib/`，不进端口。`side-by-side.tsx` 改为经 hooks 调用；写入时机与现有一致，UI 不变。

### 第 3 步：隔离假后端

- `adapters/local/index.ts` 按域拆成 `local/profile.ts`、`local/connections.ts` 等，`local/index.ts` 只做组装。
- 种子人物池、随机回复、`maybeSeedIncoming`、模拟延时统一移入 `adapters/local/fake/`，接真后端后整目录删除即可。
- `lib/people.ts` 保留类型与纯函数，数据数组移入 `fake/`。

### 第 4 步：加护栏（防止后续迭代破坏分层）

- `eslint.config.js` 增加 `no-restricted-imports`：
  - `src/routes/**`、`src/components/**` 禁止 import `@/lib/profile|sessions|intents|connections|saved-*|invites|auth|blocklist|agent|agent-memory|understanding` 的**值**（`import type` 放行），禁止 import `@/data/adapters/*`。
  - `src/data/ports/**` 禁止 import 任何适配器。
- 新增 `scripts/verify-layering.mjs`（比照现有 `verify-native-isolation.mjs`）：校验 `localStorage` / `sessionStorage` 只出现在 `adapters/local`、`lib/i18n`、`lib/seed` 与 UI 态白名单文件中；接入 `.github/workflows/build-matrix.yml`。

## 明确不做

- 不启用 Cloud、不建表、不写迁移、不实现 remote 适配器逻辑。
- 不改任何视觉、文案、路由、交互路径、动效。
- 不动 `native/`、`capacitor.config.ts`、版本脚本。

## 验证

- `lint` 0 error、`build:dev` 成功。
- 30 项单测与 Playwright e2e（smoke / interactions / flows / agent_chat）用例**不修改**即通过——行为不变才算过。
- `verify:native` 与新增 `verify:layering` 通过。

## 完成后的收益

接真实后端的改动面收敛为：新增 `adapters/remote/*` 实现 11 个端口 + 改 `src/data/index.ts` 一行 + 删除 `adapters/local/fake/`。页面与组件零改动，Lovable 可继续在 UI 层安全迭代。
