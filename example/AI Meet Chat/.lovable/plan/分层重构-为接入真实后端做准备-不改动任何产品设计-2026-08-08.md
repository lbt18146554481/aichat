# 分层重构：为接入真实后端做准备（不改动任何产品设计）

## 目标

现在的数据逻辑（localStorage 读写、同步返回、模拟延时、随机回复）和 UI 混在同一批模块里，组件直接 `import { loadProfile } from "@/lib/profile"` 之类，共 41 处引用、25 个文件直接触碰 storage。接入真实接口时，这些调用点都要从「同步」变成「异步」，会引发大面积改写。

本次只做结构分层：**同一套页面、同一套交互、同一套文案**，把数据访问收敛成可替换的一层，让下一版把 localStorage 适配器换成真实后端时，页面代码零改动或极小改动。

## 分层结构

```text
UI 层        src/routes/*, src/components/*        只用 hooks，不再直接 import 数据模块
数据钩子层   src/data/hooks/*                      useProfile / useConnections / useSavedPeople ...
端口层       src/data/ports/*.ts                   纯 TypeScript 接口 + 领域类型（异步签名）
适配器层     src/data/adapters/local/*             现有 localStorage 逻辑平移到这里（当前默认）
             src/data/adapters/remote/*            下一版新增，调用 createServerFn / 后端
领域逻辑层   src/lib/agents/*, match-reasons, questions   纯函数，不碰 storage
```

## 具体做法

1. **抽出端口接口**（新增，不动实现）
   为 8 个有状态领域各写一个接口，方法全部返回 `Promise`：
   `ProfileRepo`、`AuthRepo`、`ConnectionsRepo`、`SessionsRepo`、`IntentsRepo`、`SavedRepo`（people + wishes）、`BlocklistRepo`、`InvitesRepo`。

2. **现有实现平移为 local 适配器**
   `src/lib/profile.ts` 等文件的 storage 逻辑移入 `src/data/adapters/local/`，用同一份代码实现端口（同步逻辑包一层 `async`）。原文件保留为 re-export 薄壳，避免一次性改动所有引用点。

3. **单一装配入口**
   `src/data/index.ts` 导出 `repos`，由一处开关决定用哪套适配器（现在恒为 local）。下一版只改这一个文件。

4. **hooks 层承接异步**
   基于已有的 TanStack Query 封装 `useProfile()`、`useConnections()`、`useSavedPeople()` 等，内部用 `queryKey` + mutation。当前 local 适配器立即 resolve，行为与现在一致；换成远端后组件不需要改，只是数据晚一帧到达。

5. **组件改为消费 hooks**
   逐个把 `routes/*` 与 `components/*` 里的直接 import 换成 hooks 调用，保持 JSX、样式、文案、交互路径完全不变。已存在的 loading / empty 态复用，不新增 UI。

6. **把「假后端」隔离出来**
   `scheduleResolution` 的随机回复、`maybeSeedIncoming`、模拟 600ms 延时、种子人物池（`people.ts` / `people-extras.ts`）集中到 `src/data/adapters/local/fake/`，接真实后端时整目录删除即可，不会牵连页面。

7. **领域逻辑保持纯函数**
   `match-reasons.ts`、`agents/*` 的算分与文案生成不读 storage，改为接收数据参数。这样后端返回什么就渲染什么，同一份匹配理由代码在两种适配器下都可用。

## 边界（本次不做）

- 不启用 Lovable Cloud、不写迁移、不建表。
- 不改任何视觉、文案、交互流程、路由。
- 不动 `native/`、CI、版本脚本、合规页面。

## 对 Web 与 iOS 封装的影响（已核查）

- Web 端：只改数据的取用方式，页面结构、样式、文案、路由、交互路径均不变，产品设计零变动。
- iOS 端：`native/scripts/build-web.mjs` 通过 `vite.native.config.ts` 打包同一份 `src`，所以它会自动包含重构后的代码，但**封装方式本身不变** —— `capacitor.config.ts`、`native/ios` 工程、权限、URL Scheme、版本 xcconfig、构建脚本全部不动。
- 隔离契约不受影响：`@capacitor/*` 仍只在 `src/lib/platform/bridge.ts` 与 `src/native-entry.tsx` 中引用，新增的 `src/data/*` 不引入任何原生依赖，`verify:native` 继续通过。


## 验证

- 现有 30 项单元测试与 e2e 对话闭环用例全部通过（用例不改，行为不变即通过）。
- 原生隔离校验脚本通过。

下一版接入真实接口时的改动面：新增 `src/data/adapters/remote/*` + 修改 `src/data/index.ts` 一行开关。页面与组件不改，Lovable 可以继续在 UI 层安全迭代。
