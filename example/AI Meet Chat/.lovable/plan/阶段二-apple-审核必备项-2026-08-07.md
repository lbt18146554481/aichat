# 阶段二：Apple 审核必备项

## 目标
完成 App Store 审核必需的账号删除、隐私政策/条款页面、举报屏蔽与审核文档，同时确保现有 Web 页面不被改动。

## 两个前提确认

1. **账号删除入口必须做**：Apple 5.1.1(v) 强制要求「创建账号」的 App 必须提供 App 内账号删除。Maitri 支持注册登录，因此属于强制范围。
2. **只在 iOS 展示**：Apple 不强制 Web 端也提供删除。该入口仅在 `isIOS()` 为真时渲染，Web 上不出现。

## 改动清单

| 编号 | 内容 | 影响范围 | 说明 |
| --- | --- | --- | --- |
| 1 | 新增 `/privacy` 页面 | 纯新增路由，不影响现有页面 | App Store 隐私政策 URL 必填；内容需你确认联系邮箱和主体名称 |

| 5 | 审核文档补充 | 仅文档更新 | 在 `native/docs/ios-build.md` 追加数据声明、审核账号、截图尺寸等 |
| 6 | 回归验证 | 全流程 | test/build/build:dev/verify:native 全绿 + Web 页面截图对比 |

## 现有 Web 页面保证不动

以下页面/路由的布局、文案、交互逻辑均不改变：
- 首页 `/`
- Introduce Someone `/matchmaker`
- Do Something Together `/side-by-side`
- Connections `/connections`
- Profile `/profile`
- Me `/me`（Web 视图不增加删除入口）

新增的两个路由 `/privacy` 和 `/terms` 为独立页面，不插入也不覆盖任何现有路由。

## 需要用户确认的信息

1. 对外联系邮箱（用于隐私政策页面）。
2. 主体名称（个人或公司名）。

交付时我会用占位符并在文档中标记这两个待填项。

## 不做的事情

- 不改登录方式或邀请码逻辑。
- 不改匹配算法或推荐理由。
- 不在 Web 端提供账号删除。
- 不增加社交分享图或 SEO 额外优化。

## 技术实现说明

- 平台判断统一走 `@/lib/platform` 的 `isIOS()`，不在组件中直接引用 `@capacitor/*`。
- `isIOS()` 依赖 `window.Capacitor`，SSR 时默认 `web`，因此删除入口用 `useEffect` 挂载后渲染，避免 Web 端闪现。
- 新增文件：`src/routes/privacy.tsx`、`src/routes/terms.tsx`、`src/lib/account.ts`、`src/lib/blocklist.ts`、`src/components/delete-account.tsx`、`src/components/report-menu.tsx`。
- 少量改动：`src/routes/me.tsx`（增加 iOS 删除入口和隐私/条款链接）、`src/components/canvas/connection-thread.tsx` 和 `src/components/public-profile-sheet.tsx`（增加更多菜单入口）。
- 文案与现有项目一致，使用 `en` / `zh-CN` 两份 i18n 文件。
