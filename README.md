# nightlong —— 用聊天认识人的交友产品

> 写给同学看的产品说明：讲清楚「这个项目在做什么、用户怎么用、背后逻辑是什么」。  
> 不讲技术实现细节。若要在自己电脑上跑起来，另见文末链接。

---

## 一句话介绍

**nightlong** 是一个以 **AI 对话** 为入口的交友 / 找搭子产品。

你不是先刷一堆卡片或筛选器，而是先和一个助手聊天：说清楚你想认识什么样的人，或者想找谁一起做什么事。助手听懂之后，再一位一位把合适的人介绍给你，并说明「为什么可能合适」。

产品名可以理解为：用对话，帮人和人连上线。

---

## 它要解决什么问题

传统交友 App 常见体验是：

- 一上来就要填很多条件、滑很多头像  
- 匹配理由不清晰，「系统觉得你们合适」却说不出为什么  
- 「想交朋友」和「想找人一起打球 / 吃饭」混在一起，目标不清  

nightlong 换了一种方式：

1. **先聊天，再说清楚意图**  
2. **按意图分流**：认识新朋友，或找活动搭子  
3. **一次只认真介绍一个人**，并给出能说清的理由  
4. 不合适就换下一位，合适再往下聊  

更像有人在旁边帮你牵线，而不是冷冰冰的筛选器。

## 用户会经历怎样的主流程

### 1. 进门：先和「前台助手」聊

打开产品后，你会先和一个总入口助手对话（界面里常叫 nightlong）。  
它可以陪你随便聊聊，也会听你是不是：

- 想 **认识新朋友**（交友向）  
- 想 **找人一起做事**（活动搭子向）  

听清楚方向后，会把你带进对应的专门会话，而不是把两件事搅在一起。

### 2. 路径 A：想认识新朋友

进入「认识人」这条线之后，大致是：

1. **你说偏好**  
   例如：希望对方热情一点、同城、年龄大概多少、性格偏外向还是安静……  
   说得少也可以先找；说得越具体，后面越准。

2. **助手整理你的要求**  
   - 有些是「必须满足」的硬条件（比如性别、城市）  
   - 有些是「最好有」的软偏好（比如热情、爱读书）  
   对话里明确说出来的，会优先于资料里默认猜的。

3. **开始找人**  
   你说「帮我找」「随便推一个」之类，助手才会真正去搜，而不是每句话都推人。

4. **一位一位介绍**  
   - 左边继续聊天、听解释  
   - 右边展示这位候选人的画像、瞬间、共同点等  
   - 助手会用一两段话说明：为什么这位可能适合你（尽量说对方身上的具体点，而不是空话）

5. **你决定下一步**  
   - 想看下一位 → 换人  
   - 想改方向（比如「再安静一点」）→ 按新偏好重新找  
   - 感兴趣 → 可以继续围绕这个人聊，或进入后续联系流程（视产品阶段而定）

输入框上方有时会出现 **推荐短句**（点一下填进输入框），方便你接着说，不强制使用。

### 3. 路径 B：想找人一起做事

进入「找搭子」这条线之后，重点变成：

1. **你说想一起做什么**  
   例如：周末跑步、找人吃饭、一起看展……

2. **补齐必要信息**  
   尤其是 **地点**（某座城市、线上、或不限）。  
   若你资料里已有城市，系统会先按你的城市当作默认地点（当作硬条件用），你也可以改。

3. **开始找愿意一起做这件事的人**  
   同样是一位一位介绍，并说明和这次活动的匹配点。

4. **暂时没人时**  
   会把你的邀约先挂着，之后有合适的人再提醒；你也可以改条件再试。

两条路径在体验上分开：  
**认识人** 看重长期气质与偏好；**找搭子** 看重「这件事能不能一起做成」。

## 产品逻辑（用白话讲）

可以把整个系统想成三位「分工不同的助手」，用户界面上尽量不暴露内部名字，都像同一个人在帮你：

| 角色（对内） | 对用户来说在干什么 |
|--------------|-------------------|
| 前台 / 接待 | 寒暄、分辨你是要交友还是找搭子，再带你进对应房间 |
| 认识人助手 | 听偏好 → 筛选 → 排序 → 一位一位介绍 + 说理由 |
| 找搭子助手 | 听活动 → 确认地点等关键信息 → 找愿意一起做的人 |

### 「硬条件」和「软偏好」

- **硬条件**：不满足就直接不考虑（例如明确只要某性别、某城市）。  
- **软偏好**：不满足仍可能出现，但排序会靠后（例如「最好热情一点」）。

对话里你 **亲口说出来的**，权重高于系统根据资料猜的默认条件。  
例如你说「帮我找个热情的女孩」，会优先找气质偏热情、开朗的人，而不是只因为资料里别的巧合就推一个很安静的人。

### 为什么一次只介绍一个人

- 降低选择负担：认真看一个人，而不是同时比对十个  
- 理由更具体：每一次介绍都能说清「为什么是 TA」  
- 节奏更自然：像朋友介绍，而不是瀑布流刷卡

### 匹配时大概在看什么（仍不讲技术）

介绍一个人之前，系统大致会：

1. 先用硬条件筛掉明显不符合的人  
2. 再按你口头说的偏好、性格兴趣等，给剩下的人打分排序  
3. 必要时再用 AI 根据双方材料写介绍理由、微调顺序  
4. 最后把排在前面的人，一位一位呈现给你  

没有候选人数据时，助手会老实告诉你「现在库是空的」，而不是瞎编一个人。

## 界面上你会看到什么

- **聊天区**：和助手对话的主舞台  
- **右侧资料卡**：当前介绍的人是谁、画像、瞬间、为什么合适等  
- **输入框上方的推荐回复**：可选的下一句快捷说法  
- **会话列表**：可以分别开「认识人」「找搭子」等不同对话，互不打乱  

语言上：你用中文聊，助手用中文回；你用英文聊，助手尽量用英文回（跟你怎么写，而不是只跟界面按钮语言）。

## 这个项目目前适合展示什么

适合向同学演示的点：

1. **对话驱动的交友入口**，而不是传统滑卡  
2. **意图分流**：认识朋友 vs 找活动搭子  
3. **一人一介 + 可解释的理由**  
4. **口头需求优先**：你刚说的话，比冷冰冰的默认画像更管用  
5. **真实空库提示**：没数据时会明确说，方便理解系统边界  

不适合夸大成：已经是成熟的大型社交平台、或已经覆盖全网真人匹配——当前更像 **产品原型 + 可演示的智能牵线流程**，候选人库可以是演示数据。

---

## 和「普通聊天机器人」差在哪

| 普通聊天机器人 | nightlong |
|----------------|--------|
| 主要陪聊、答问题 | 以「帮你认识人 / 找搭子」为目标 |
| 通常不连真实人选库 | 会从候选人池里真正挑人并展示卡片 |
| 很少持续记住你的择偶/搭子条件 | 会把对话里的条件整理进后续匹配 |
| 一次给很多建议 | 控制节奏，一位一位介绍 |

## 小结

**nightlong 用聊天代替刷卡，先听懂你要什么，再一位一位把可能合适的人介绍给你，并说清为什么。**

它把「交友」和「找活动搭子」分成两条清晰路径，让偏好可积累、介绍可解释、节奏可控制——这是这个项目最想证明的产品逻辑。
